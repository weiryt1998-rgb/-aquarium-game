# ☁️ เซฟกลางบน Firebase (แผน Spark — ฟรี)

ทุกอุปกรณ์ที่เข้าสู่ระบบด้วย **บัญชีผู้เล่นหลักบัญชีเดียว** (กรอกแค่รหัสผ่านเกม) จะเล่นเซฟชุดเดียวกันที่ `gameSaves/global` บน Cloud Firestore
และเห็นข้อมูลล่าสุดตรงกันแบบเรียลไทม์

- ใช้แค่ **Firebase Authentication (Email/Password)** และ **Cloud Firestore** บนแผน **Spark (ฟรี 100%)**
- **ไม่ใช้** Cloud Functions, SQL หรือบริการที่ต้องอัปเกรดเป็น Blaze
- ไม่มีรหัสผ่านหรือข้อมูลลับในโค้ด — รหัสผ่านอยู่ใน Firebase Authentication เท่านั้น

## ภาพรวมการทำงาน

```
 ผู้เล่น (ทุกเครื่องใช้รหัสผ่านเกมเดียวกัน)
   │ 1) กรอกรหัสผ่าน → Firebase Authentication (บัญชีผู้เล่นหลัก 1 บัญชี, Email/Password)
   │    รหัสผ่านส่งตรงไป Firebase เท่านั้น — ไม่เก็บในโค้ด / LocalStorage / Firestore
   ▼
 หน้าเกม ──2) โหลดเซฟกลางก่อนเริ่มเล่น (gameSaves/global) — โหลดไม่สำเร็จ = ยังไม่เริ่มเกม และไม่เขียนอะไรทับ
   │      3) ฟังการเปลี่ยนแปลงแบบเรียลไทม์ (onSnapshot) → ปลา/เงินที่อีกเครื่องเปลี่ยนโผล่ในฉากทันที
   │
   │ 4) เล่นเกม: ทุกการกระทำที่มีผลกับเงิน/ของ ถูกบันทึกเป็น "คำสั่ง" (ซื้อปลา, ขาย, เก็บเหรียญ, รับรางวัล ฯลฯ)
   │    รวมเป็นชุด (commit) — คำสั่งด่วน (ซื้อ/ขาย/รางวัล) ส่งใน ~0.4 วินาที ที่เหลือรวมส่งทุก ~15 วินาที
   ▼
 Firestore transaction: อ่านเซฟล่าสุดบนเซิร์ฟเวอร์ → เล่นคำสั่งซ้ำบนข้อมูลนั้นด้วยกฎเกม (src/shared/) → เขียน revision + 1
   ▼
 Security Rules (firestore.rules): เฉพาะ UID บัญชีหลัก · revision ต้องต่อจากค่าบนเซิร์ฟเวอร์พอดี · เวลาเป็นของเซิร์ฟเวอร์
                                   · รูปแบบ/ช่วงค่าถูกต้อง · ลบเซฟไม่ได้ · จุดสำรองแก้/ลบไม่ได้
```

หลักการกันข้อมูลหาย/ซ้ำ:

| ปัญหา | วิธีป้องกัน |
| --- | --- |
| เขียนค่าเริ่มต้นทับเซฟบนคลาวด์ | เกมเริ่มหลังโหลดเซฟสำเร็จเท่านั้น และการสร้างเซฟครั้งแรกเป็น transaction แบบ "สร้างถ้ายังไม่มี" (กดพร้อมกันหลายเครื่องก็ได้เซฟเดียว) |
| เซฟเก่าทับเซฟใหม่ | ทุกการบันทึกทำใน **Firestore transaction** และเพิ่ม **`revision`** ทีละ 1 — Rules ปฏิเสธการเขียนที่ revision ไม่ต่อจากค่าบนเซิร์ฟเวอร์ · ถ้าอีกเครื่องเพิ่งบันทึก transaction จะอ่านข้อมูลใหม่แล้วเล่นคำสั่งซ้ำให้เอง |
| ส่งซ้ำแล้วจ่ายเงิน/ได้รางวัลซ้ำ | แต่ละหน้าเกมมีรหัส (`writer`) และเลขลำดับ (`seq`) ที่จำไว้ในเซฟ — ส่ง seq เดิมซ้ำกี่ครั้งก็บันทึกครั้งเดียว |
| เปิดหลายเครื่องพร้อมกันแล้วเงินงอก | เหรียญจากปลาจำกัดด้วย "ธนาคารเหรียญ" ต่อตู้ที่เติมตามอัตราผลิตสูงสุดของปลาตามเวลาจริง |
| เน็ตหลุด / ปิดแท็บก่อนบันทึก | คำสั่งที่ยังไม่ส่งเก็บในคิวชั่วคราว (localStorage) แล้วส่งต่อเมื่อออนไลน์/เปิดเกมใหม่ โดยเล่นซ้ำบนเซฟล่าสุด **ไม่ใช่เอาทั้งเซฟในเครื่องไปทับ** (คิวเก่ากว่า 7 วันถูกทิ้ง) |
| รีเซ็ต/กู้คืนขณะอีกเครื่องเล่นอยู่ | `epoch` เพิ่มขึ้น → คำสั่งค้างจากก่อนหน้าถูกยกเลิกทั้งหมด และอีกเครื่องถูกขอให้โหลดใหม่ |

สถานะที่ผู้เล่นเห็น (ป้ายใต้ปุ่มมุมขวาบน กดเพื่อเปิดหน้า "เซฟคลาวด์"):
`☁️ บันทึกแล้ว hh:mm:ss` · `☁️ รอบันทึก` · `⏳ กำลังบันทึก…` · `📴 ออฟไลน์ · ยังไม่ได้บันทึก` · `⚠️ บันทึกไม่สำเร็จ · กำลังลองใหม่` · `⛔ หยุดบันทึก`
— จะแสดง "บันทึกแล้ว" ก็ต่อเมื่อ Firestore ยืนยันการเขียนจริงเท่านั้น

## สิ่งที่ต้องตั้งค่าใน Firebase Console

> ⚠️ **อย่าใช้โปรเจกต์ `project2-ff906`** (ของระบบจัดเก็บเอกสารราชการใน `Desktop/MyProject`)
> ถ้า deploy rules ของเกมลงไปจะ **ทับ rules ของระบบเอกสาร** และโควตาฟรีรายวันจะถูกใช้ร่วมกัน — สร้างโปรเจกต์ใหม่สำหรับเกม (ฟรี)
> สคริปต์ deploy ของโปรเจกต์นี้จะปฏิเสธถ้าเลือกโปรเจกต์นั้น

ทุกขั้นตอนอยู่บนแผน Spark — **ไม่ต้องผูกบัตร และไม่ต้องกดอัปเกรด** (ถ้า Console ชวนอัปเกรด ให้ข้าม)

1. **สร้างโปรเจกต์ใหม่** — <https://console.firebase.google.com> → Create a project (เช่น `aquarium-game`) จะปิด Google Analytics ก็ได้
2. **เพิ่ม Web app** — ⚙️ Project settings → General → Your apps → `</>` (Web) → ตั้งชื่อ → คัดลอกค่า `firebaseConfig`
   (apiKey, authDomain, projectId, appId) ไว้ใช้ใน[ขั้นตอนตั้งค่าหน้าเว็บ](#ตั้งค่าหน้าเว็บ-และ-deploy-security-rules) — ไม่ต้องเปิด Firebase Hosting
3. **เปิด Authentication แบบ Email/Password**
   - Build → Authentication → Get started → Sign-in method → **Email/Password** → Enable (ไม่ต้องเปิด Email link และ**ไม่ต้องเปิด Anonymous**)
   - Settings → **Authorized domains** → เพิ่มโดเมนที่ใช้เล่นเกม เช่น `xxx.netlify.app`, `weiryt1998-rgb.github.io`
   - (แนะนำ) Settings → User actions → ปิด **Enable create (sign-up)** — กันคนสมัครบัญชีเองด้วย API key
     (ถึงไม่ปิด บัญชีที่สมัครเองก็เข้าเซฟไม่ได้ เพราะ Rules อนุญาตเฉพาะ UID บัญชีหลัก)
4. **สร้าง Cloud Firestore** — Build → Firestore Database → Create database → **Standard edition** → **Production mode**
   → location **`asia-southeast1` (Singapore)** (เลือกแล้วเปลี่ยนไม่ได้) — ไม่ต้องสร้าง collection เอง เกมสร้าง `gameSaves/global` ให้ตอนเข้าครั้งแรก
5. **สร้างบัญชีผู้เล่นหลัก + ตั้งรหัสผ่านเกม** — Authentication → Users → **Add user** (ดู[หัวข้อถัดไป](#ตั้ง--เปลี่ยนรหัสผ่านเกม))
   แล้ว**คัดลอก User UID** ของบัญชีนั้น
6. **ใส่ UID ลง Security Rules แล้ว deploy** — ทำในเครื่อง (ดู[ขั้นตอน deploy](#2-ใส่-uid-และ-deploy-security-rules)):
   `npm run set-player-uid -- <UID>` → `npm run deploy`
   (ถ้ายังไม่ได้ทำ เมื่อเข้าเกมจะเห็นหน้า "ยังไม่ได้รับสิทธิ์" พร้อม UID และคำสั่งให้คัดลอก)

ไม่ต้องตั้ง Budget, Billing, Cloud Functions, App Engine หรือ service account ใด ๆ

## ตั้ง / เปลี่ยนรหัสผ่านเกม

รหัสผ่านเกม = รหัสผ่านของบัญชีผู้เล่นหลักใน Firebase Authentication (Firebase เก็บแบบ hash และจำกัดการเดารหัสให้เอง)
**ไม่มีรหัสผ่านเริ่มต้นใด ๆ ในระบบ** — เกมใช้งานไม่ได้จนกว่าผู้ดูแลจะตั้งเอง

**ข้อแนะนำ:** ใช้วลียาว 4–5 คำที่เดายาก (อย่างน้อย 12 ตัวอักษร) · แจ้งผู้เล่นผ่านช่องทางส่วนตัว · ห้ามใส่รหัสในโค้ด, `.env`, README, issue หรือแชตกลุ่มสาธารณะ

### วิธี A — ผ่าน Firebase Console (แนะนำ ไม่ต้องติดตั้งอะไร)

1. Authentication → Users → **Add user**
   - Email: อีเมลของบัญชีหลัก เช่น `player@your-domain.example` (ไม่ต้องเป็นอีเมลจริง ถ้าไม่ต้องการใช้ปุ่ม "Reset password" ภายหลัง)
   - Password: รหัสผ่านเกม
2. คัดลอก **User UID** → `npm run set-player-uid -- <UID>` → `npm run deploy`
3. ใส่อีเมลเดียวกันใน `VITE_GAME_ACCOUNT_EMAIL`

**เปลี่ยนรหัสผ่านภายหลังผ่าน Console:** Console ไม่มีช่องตั้งรหัสใหม่ให้บัญชีเดิมโดยตรง (มีแค่ส่งอีเมลรีเซ็ต — ใช้ได้ถ้าอีเมลบัญชีเป็นอีเมลจริง) จึงทำได้โดย
ลบบัญชีเดิม → Add user ใหม่ด้วยอีเมลเดิมและรหัสใหม่ → `npm run set-player-uid -- <UID ใหม่>` → `npm run deploy`
(อุปกรณ์ที่ยังล็อกอินด้วยบัญชีเก่าจะเข้าเซฟไม่ได้ทันทีหลัง deploy — **เซฟไม่ได้รับผลกระทบ** เพราะเซฟไม่ได้ผูกกับบัญชี)

### วิธี A2 — เปลี่ยนอีเมล/รหัสผ่านของบัญชีเดิม (UID เดิม, แนะนำเมื่อมีบัญชีแล้ว)

ใช้ Firebase Admin SDK กับสิทธิ์ของบัญชี Firebase CLI ที่ผูกกับโฟลเดอร์นี้ (ไม่ต้องมีไฟล์ service account)
ไม่ลบ/สร้างบัญชี ไม่แตะเซฟเกมหรือ Security Rules จึงไม่ต้อง deploy ใหม่

```bash
npm run account:check  -- --project fish-game-606c9   # ตรวจสิทธิ์ + โปรเจกต์ + UID + อีเมลใน .env.local (ไม่เปลี่ยนอะไร)
npm run account:update -- --project fish-game-606c9   # ต้องรันใน Terminal จริง
#   1) อีเมลใหม่ (Enter = ใช้อีเมลเดิม) — ตรวจว่าไม่ซ้ำกับบัญชีอื่น
#   2) รหัสผ่านใหม่ 2 ครั้ง (ไม่แสดงบนจอ อย่างน้อย 12 ตัวอักษร)
#   3) เลือกว่าจะให้อุปกรณ์อื่นออกจากระบบไหม
#   4) ดูสรุป → พิมพ์ "ยืนยัน" จึงจะเปลี่ยนจริง (อย่างอื่น = ยกเลิก)
#   → อัปเดตบัญชี, ทดลองล็อกอินด้วยรหัสใหม่, แก้ VITE_GAME_ACCOUNT_EMAIL ใน .env.local ให้ตรง
```

ถ้าเว็บจริงอยู่บน Netlify/GitHub Pages ต้องแก้ตัวแปร `VITE_GAME_ACCOUNT_EMAIL` ที่นั่นด้วยแล้ว build ใหม่

### วิธี B — สคริปต์ตั้งรหัส (เปลี่ยนรหัสโดย UID เดิม + ใส่ UID ลง Rules ให้)

ใช้ Firebase Admin SDK จากเครื่องของผู้ดูแล (ทำงานบนแผน Spark ได้ ไม่ใช่ Cloud Functions)

```bash
npm --prefix functions install                 # ครั้งแรก (ติดตั้ง firebase-admin)
gcloud auth application-default login          # ล็อกอินบัญชี Google ของผู้ดูแลโปรเจกต์ (หรือใช้ GOOGLE_APPLICATION_CREDENTIALS)
node functions/scripts/set-game-password.mjs --project <project-id> --email player@your-domain.example
#   พิมพ์รหัสผ่านใหม่ 2 ครั้ง (ไม่แสดงบนจอ ไม่บันทึกลงไฟล์) → สร้าง/เปลี่ยนรหัส แล้วใส่ UID ลง firestore.rules ในเครื่อง
#   เพิ่ม --revoke เพื่อบังคับทุกอุปกรณ์ออกจากระบบ (เช่น รหัสเดิมรั่ว)
npm run deploy                                 # ถ้า UID เปลี่ยน (สร้างบัญชีใหม่)
```

- ถ้าใช้ไฟล์ service account: สร้างที่ Project settings → Service accounts → Generate new private key → **เก็บไว้นอกโฟลเดอร์โปรเจกต์**
  ตั้ง `GOOGLE_APPLICATION_CREDENTIALS=<path>` ระหว่างรัน แล้ว **ลบกุญแจทิ้ง** (Google Cloud Console → IAM → Service accounts → Keys) เมื่อเสร็จ
  `.gitignore` กันไฟล์ชื่อ `*service-account*.json` / `*-firebase-adminsdk-*.json` ไว้แล้ว แต่ไม่ควรวางไว้ในโปรเจกต์ตั้งแต่แรก
- เปลี่ยนรหัสผ่านแล้ว อุปกรณ์อื่นต้องกรอกรหัสใหม่ภายใน ~1 ชั่วโมง (อายุ ID token)

## ตั้งค่าหน้าเว็บ และ deploy Security Rules

### 1) ค่าตั้ง Firebase ของหน้าเว็บ

คัดลอก `.env.example` เป็น `.env.local` (ไม่ถูก commit) แล้วใส่ค่าจากขั้นตอนที่ 2:

```ini
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=your-project.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=your-project
VITE_FIREBASE_APP_ID=...
VITE_GAME_ACCOUNT_EMAIL=player@your-domain.example
```

ค่าเหล่านี้ไม่ใช่ความลับ (Firebase web config ออกแบบให้เปิดเผยได้) ความปลอดภัยอยู่ที่ Authentication + Security Rules
`VITE_CLOUD_SAVE_MODE` ไม่ต้องตั้ง (ค่าเริ่มต้นคือแผน Spark)

- **Netlify**: Site configuration → Environment variables → เพิ่มตัวแปร `VITE_*` ข้างบน → Deploys → Trigger deploy
- **GitHub Pages**: repo → Settings → Secrets and variables → Actions → แท็บ **Variables** → เพิ่มตัวแปร `VITE_*` ข้างบน
  (workflow `.github/workflows/deploy.yml` ส่งค่าให้ตอน build แล้ว) → push ขึ้น `main`

ถ้ายังไม่ได้ตั้งค่า เกมจะแสดงหน้า "ยังไม่ได้ตั้งค่า Firebase" พร้อมรายชื่อตัวแปรที่ขาด

ตรวจค่าตั้งทั้งหมดในเครื่อง (ไม่เชื่อมต่อ Firebase): `npm run check:firebase`
— ตรวจตัวแปร `VITE_*`, โหมด Spark, UID ใน Rules, โปรเจกต์ใน `.firebaserc` และว่า `firebase.json` ไม่มี Cloud Functions

### 2) ใส่ UID และ deploy Security Rules

```bash
npm run set-player-uid -- <UID>        # ใส่ UID บัญชีหลักลง firestore.rules (แก้ไฟล์ในเครื่องเท่านั้น)
npm run firebase -- login              # ล็อกอิน Firebase CLI (เปิดเบราว์เซอร์)
npm run firebase -- use --add          # เลือกโปรเจกต์ของเกม (สร้างไฟล์ .firebaserc)
npm run check:firebase                 # ตรวจก่อน
npm run deploy                         # deploy เฉพาะ Firestore Security Rules + indexes (ไม่มี Cloud Functions)
```

- `npm run deploy` ตรวจให้อัตโนมัติก่อนทุกครั้ง: ถ้ายังไม่ได้ใส่ UID หรือเลือกโปรเจกต์ `project2-ff906` จะหยุดโดยไม่ deploy
- UID ไม่ใช่ความลับ commit ไฟล์ `firestore.rules` ที่ใส่ UID แล้วได้
- `npm run firebase` เรียก Firebase CLI เวอร์ชันที่ทดสอบแล้ว (`firebase-tools@15.31.0`) ผ่าน npx ไม่ต้องติดตั้งถาวร
- ตรวจผลใน Console: Firestore Database → Rules → ต้องเห็น `function playerUid() { return '<UID ของคุณ>'; }`

## ย้ายเซฟเดิมจากเบราว์เซอร์

เซฟเดิมของเกมอยู่ใน localStorage คีย์ `aquarium-game-save` (เครื่องใครเครื่องมัน)

- **ยังไม่มีเซฟกลาง**: เครื่องที่มีเซฟเดิมจะถูกถามก่อนว่า "นำเข้าเซฟจากเครื่องนี้" หรือ "เริ่มใหม่" — นำเข้าแบบ transaction (ถ้าอีกเครื่องสร้างเซฟกลางไปก่อน จะไม่ทับ)
- **มีเซฟกลางแล้ว**: ระบบ **ไม่ทับอัตโนมัติ** — เลือกได้ว่าจะเล่นเซฟกลางต่อ, ดาวน์โหลดเซฟเครื่องนี้เก็บไว้ (JSON), หรือแทนที่เซฟกลาง
  (ต้องพิมพ์ "แทนที่" ยืนยัน และระบบสำรองเซฟกลางเดิมเป็นจุดสำรอง `before-replace` ก่อนเสมอ)
- เซฟเดิมในเครื่อง**ไม่ถูกลบหรือแก้ไข** ไม่ว่าจะเลือกทางไหน — ค่าที่ผิดรูปแบบถูกปรับให้อยู่ในช่วงที่ถูกต้องก่อนนำเข้า

## สำรองและกู้คืน

- **อัตโนมัติ**: สำรองวันละครั้ง (ก่อนการบันทึกแรกของวัน) และทุกครั้งก่อน รีเซ็ต / กู้คืน / นำเข้าเซฟเก่า / เปลี่ยน schema
- **ในเกม**: ป้ายสถานะเซฟ (หรือ เมนู ☰ → เซฟคลาวด์) → ดูจุดสำรอง, กด "กู้คืน" (ยืนยัน 2 ครั้ง ระบบสำรองข้อมูลปัจจุบันก่อนกู้), "สร้างจุดสำรองตอนนี้", "ดาวน์โหลด JSON" เก็บไว้ในเครื่อง
- **รีเซ็ตเกม** (ตั้งค่า → รีเซ็ตเซฟ): มีผลกับทุกอุปกรณ์ และสำรองข้อมูลเดิมไว้ก่อนเสมอ
- จุดสำรองลบจากหน้าเว็บไม่ได้ (กันลบโดยไม่ตั้งใจ) ถ้ามีมากเกินไปลบเองได้ที่ Firestore Console → `gameSaves/global/backups`
- กู้คืนด้วยมือ (กรณีฉุกเฉิน): Firestore Console → `gameSaves/global/backups` → เปิดจุดสำรอง → ข้อมูลเกมอยู่ในฟิลด์ `game`

## วิธีทดสอบข้ามอุปกรณ์ (ของจริง)

หลังตั้งค่าและ deploy แล้ว:

1. คอมพิวเตอร์: เปิดเกม → กรอกรหัสผ่านเกม → (ครั้งแรก) สร้าง/นำเข้าเซฟกลาง → กด "เริ่มเล่น"
2. ซื้อปลา (ร้านค้า → เลือกปลา → ซื้อ) → ดูป้ายมุมขวาบนจนเป็น **☁️ บันทึกแล้ว** → จดจำนวนเงินและจำนวนปลา (ป้ายใต้เงิน "ปลา x/14 ตัว")
3. มือถือ/เบราว์เซอร์อื่น: เปิดเกม → กรอกรหัสเดียวกัน → เงิน ปลา อาหาร ภารกิจ ต้องตรงกับเครื่องแรก
4. ในเครื่องที่สอง ซื้ออาหารหรือขายปลา → เครื่องแรกต้องเห็นเงิน/ปลาเปลี่ยนเองภายในไม่กี่วินาที และมีแจ้งเตือน "มีการเปลี่ยนแปลงจากอุปกรณ์อื่น"
5. รีเฟรชทั้งสองเครื่อง → ข้อมูลยังอยู่ และไม่ต้องกรอกรหัสใหม่
6. ทดสอบรหัสผิด → ต้องขึ้น "รหัสผ่านไม่ถูกต้อง" และเข้าเกมไม่ได้
7. ปิด Wi-Fi ในเครื่องหนึ่งแล้วซื้อของ → ป้ายต้องเป็น "ออฟไลน์ · ยังไม่ได้บันทึก" → เปิด Wi-Fi → กลับเป็น "บันทึกแล้ว" และอีกเครื่องเห็นการซื้อนั้น
8. ซื้อพร้อมกันสองเครื่อง → ต้องได้ของครบทั้งสองชิ้นและเงินถูกหักครบ (ถ้าเงินไม่พอสำหรับทั้งคู่ เครื่องหนึ่งจะถูกแจ้งว่าไม่สำเร็จและข้อมูลถูกปรับให้ตรงกัน)
9. ตรวจใน Firestore Console: `gameSaves/global` → `revision` เพิ่มขึ้นทุกการบันทึก, `backups` มีจุดสำรองรายวัน

## ข้อจำกัดและความเสี่ยงที่ควรรู้

- **บัญชีหลักบัญชีเดียว**: ทุกคนที่รู้รหัสผ่านมีสิทธิ์เท่ากัน (รวมถึงรีเซ็ต/กู้คืน — แต่มีจุดสำรองให้ย้อนได้) และระบบแยกไม่ได้ว่าใครทำอะไร
  ถ้ารหัสรั่ว ให้เปลี่ยนรหัสด้วยสคริปต์พร้อม `--revoke` หรือสร้างบัญชีใหม่แล้วตั้ง UID ใหม่ใน Rules + deploy
- **แผน Spark ไม่มีเซิร์ฟเวอร์ตรวจการซื้อขาย**: กฎเกมรันในเบราว์เซอร์ภายใน transaction และ Rules ตรวจได้แค่ "รูปแบบ ลำดับ revision และช่วงค่า"
  ผู้ที่รู้รหัสผ่านและเขียน Firestore เองผ่าน DevTools ยังแก้เงิน/ของได้ภายในขอบเขตที่ Rules อนุญาต (คนที่ไม่รู้รหัสผ่านทำอะไรไม่ได้เลย)
  — ถ้าต้องการกันกรณีนี้ต้องใช้ Cloud Functions ซึ่งต้องใช้แผน Blaze ([ภาคผนวก](#ภาคผนวก-แผน-blaze-ไม่บังคับ))
- **สองเครื่องเปิดตู้เดียวกันพร้อมกัน**: ค่าความหิว/สุขภาพจะสลับกันยึดค่าของเครื่องที่บันทึกล่าสุด อาจเห็นแถบค่ากระโดดเล็กน้อย (ไม่กระทบเงินหรือของ)
- **ต้องออนไลน์ตอนโหลดครั้งแรก** บนเครื่องใหม่ ถ้าเคยโหลดแล้วและเน็ตหลุด จะเปิดจากข้อมูลแคชพร้อมแจ้งว่าเป็นข้อมูลออฟไลน์
- **คิวออฟไลน์เก่ากว่า 7 วัน** ถูกทิ้งเพื่อไม่ให้ข้อมูลเก่ามากทับสถานะปัจจุบัน
- **ภารกิจรายวัน/รางวัลประจำวัน** รีเซ็ตเที่ยงคืนตามเวลาไทย (`CONFIG.timeZone`) พร้อมกันทุกเครื่อง
- ถ้าเปลี่ยนรหัสผ่าน อุปกรณ์ที่ล็อกอินค้างอยู่จะหลุดภายในไม่เกิน ~1 ชั่วโมง (อายุ ID token) — สิ่งที่ยังไม่บันทึกถูกเก็บในคิวและส่งหลังล็อกอินใหม่
- เพิ่มความปลอดภัยได้อีก (ไม่บังคับ ฟรี): เปิด App Check (reCAPTCHA) และจำกัด API key ตาม HTTP referrer ใน Google Cloud Console

## ภาคผนวก: แผน Blaze (ไม่บังคับ)

โปรเจกต์ยังเก็บโหมด `functions` ไว้เผื่อย้ายไปแผน Blaze ภายหลัง (**ไม่ถูกใช้ ไม่ถูก deploy** ถ้าไม่สั่งเอง):
Cloud Functions (`functions/`) ตรวจทุกคำสั่งซื้อขาย/รางวัลฝั่งเซิร์ฟเวอร์ และหน้าเว็บเขียน Firestore เองไม่ได้เลย

| | แผน Spark (ค่าเริ่มต้น) | แผน Blaze (ภาคผนวก) |
| --- | --- | --- |
| ค่าใช้จ่าย / ผูกบัตร | ฟรี / ไม่ต้อง | มีโควตาฟรี แต่ต้องผูกบัตร ไม่มีเพดานหยุดเอง |
| ใครเขียนเซฟ | หน้าเว็บ (transaction + Rules) | Cloud Functions เท่านั้น |
| สิทธิ์ | UID บัญชีหลักใน `firestore.rules` | รายชื่อ `gameAccess/{uid}` ใน `firestore.blaze.rules` |
| ไฟล์ตั้งค่า | `firebase.json` | `firebase.blaze.json` |

ย้ายไป Blaze: อัปเกรดแผน + ตั้ง Budget alert → สร้าง `gameAccess/<UID>` (field `role` = `player`) → ตั้ง `VITE_CLOUD_SAVE_MODE=functions`
→ `npm --prefix functions install && npm run deploy:blaze` · ทดสอบ: `npm run test:functions`, `npm run test:e2e:blaze` · ข้อมูลเซฟใช้ต่อได้เลยไม่ต้องย้าย
